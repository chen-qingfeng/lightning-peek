# 闪电看图 · 安卓真机验证说明

这份说明是写给 jinyan 的。这一版**只用来试**，看手机打不打得开图纸、要多久、占多少内存。它不是正式版，不上应用商店，也不要拿去发给客户。

苹果手机这次不做。

图纸只在你的手机里打开，程序不会把图纸传到网上。

---

## 1. 现在只装一个包

华为真机上，一上来要 1 GB 的原始包加载图纸模块会失败。后面的安装包只用调小内存的那一份：先要 64 MB，不够再增加。

到 GitHub 仓库的 **Actions** 页面，打开名字叫 **「安卓验证包」**、带绿色勾的最新一次运行。页面最下面只有一个文件：

**LightningPeek-android-debug**

下下来的是 zip。解开以后点里面的 **.apk** 安装。不要装以前的 `stock` 或 `smallmem` 包。桌面上的名字仍是「闪电看图」。验证面板默认是收起的，点「展开」才能看到数据。

## 2. 允许安装「未知来源」的应用

这个包没有上架，手机第一次安装会拦住。各家手机的菜单位置不一样，大致是：

1. 打开 **设置**。
2. 找 **安全**、**隐私**，或 **应用和通知**。
3. 找 **安装未知应用**（有的叫「外部来源应用」）。
4. 选中你用来打开 apk 的那个软件（文件管理、浏览器或微信），把 **允许安装** 打开。
5. 再点一次 apk，按提示安装。

如果系统问你要不要「发送到安全扫描」，可以跳过。只有确认这个 apk 是从上面的 Actions 页面下载的，才安装。

装好后桌面上会出现「闪电看图」。

## 3. 打开 3 张图

准备你平时会看的 **3 张图**，最好一大一小都有，其中一张是以前在电脑上比较慢的那张。图留在手机里就行，**不要发到 GitHub，也不要提交到仓库**。

每一张图、每一个包都做一遍：

1. 打开闪电看图。
2. 点 **打开图纸**，从手机文件里选出这一张。不要用「分享」以外的办法改文件。
3. 等图出现。右下角有一块深色的 **验证数据**。
4. 点 **复制**。文字会进剪贴板。把它粘到备忘录，或直接粘到下面的表里。
5. 如果复制按钮变成「请长按复制」，就长按下面那一框白字，选复制。

看完一张可以关掉程序再开下一张，这样数字不会和上一张混在一起。面板里最多留最近 3 次。

面板上还有一行开关：「每张图单独转换，转完就丢掉 DWG 模块」。**先不要开**，按默认再测一遍即可。如果某个包总是越开越卡，可以打开这个开关再测同一张图，并在备注里写「开了单独转换」。

包里还带了两张公开的泵房样图和一个很小的合成天正字。那是用来确认程序本身能打开，**不能代替你的 3 张图**。按钮在验证面板里。

面板上的 PSS、RSS 是这个程序自己这个进程的数。有的手机会把画图放在另一个「沙箱」进程里，面板读不到。读不到时，电脑上连着这台手机执行：

```
adb shell dumpsys meminfo 闪电看图
adb shell ps -A | grep sandboxed
```

把这两段输出一起发回来。

## 5. 两个包怎么比

同一张图，原始包和调小内存包各开一次，比这几件事：

- 能不能打开（白屏、闪退、一直转圈，都算不能）。
- 「从选中到画完」差多少。
- wasm 那一行有没有从 64MB 往上长。调小内存包如果图比较大，这里应该会变大，这是预期的。
- PSS、RSS 哪个更高。PSS 是系统认为这个程序占的内存，优先看它。

把两份「复制」出来的文字一起发回来，比只填表更好。

## 6. 闪退、打不开时怎么说

请尽量带上这些：

1. 是哪一个包（原始还是调小内存）。
2. 图的文件名和大概大小（不用发图本身）。
3. 停在哪一步：一点开程序就退、选出文件以后退、转圈很久、刚画出一点就白屏。
4. 验证面板里能复制到的文字。如果来不及复制，就截一张屏。
5. 上面的机型、安卓版本、WebView、32/64 位。

发到仓库的 Issues，或直接回复给做这个试验的人。标题写「安卓验证：打不开」就行。

如果手机提示「解析安装包出错」，多半是下载没下完整，重新从 Actions 下载一次。

## 给一起看结果的人（技术记录）

验证壳在 `mobile/`。网页仍只有 `app/` 里那一份，构建时复制到 `mobile/www`，不在仓库里存第二份页面。桌面版的 wasm 原文件没有改。

内存实验（`npm test` 已通过，68 项里含下面这些）：

- 原 wasm 内存段：初始 **16384 页 = 1024 MiB**，上限 **65536 页 = 4 GiB**。内存是模块自己导出的。
- 调小内存包把初始页数改成 **1024 页 = 64 MiB**。2048 页（128 MiB）也试过，能加载。改的是内存段里初始页数的 3 字节 LEB128，全文件只动了 **2 个字节**，上限仍是 65536 页。
- 胶水 `libredwg-web.js` 里没有 `INITIAL_MEMORY`，也没有 `new WebAssembly.Memory`。需要更多内存时走 `_emscripten_resize_heap` → `growMemory` → `wasmMemory.grow`。
- `tarch.js` 用对象指针 `obj >> 2` 再加字段偏移（`U[w+4]`、`U[w+18]`、`U[w+28]`），没有写死绝对地址。因为没有重编，这些偏移不用重对。
- 合成天正样图 `docs/samples/tarch-note.dwg`（自己生成，不是真实项目）：一个 `TCH_TEXT`，文字是「消防」，插入点 (71796.85, 25636.74)，字高 3.5，出图比例 100。在 1024 页和 2048 页上都能读出来。
- 堆增长：用 1024 页的模块读一张自己生成的、有 45000 条直线的图。DXF 路径（`dxf_read_file`，`npm test` 会跑）堆从 **67108864** 长到 **103350272**（约 64 MiB → 99 MiB）。同一张图写成 DWG 后再走程序真正用的 `dwg_read_file`，读完同样到 99 MiB；接着 `dwg_write_dxf`（开 DWG 时一定会做）继续长到 **165019648**（约 157 MiB）。20000 条直线时堆还没越过 64 MiB。这张大图没有放进仓库。增长发生在解析和写出 DXF 时，不是在把文件字节写进模块的那一下。
- 调小内存只用于安卓壳。桌面版仍是原来的 16384 页。

模拟器（Android 14，API 34，x86_64，WebView 113.0.5672.136，内存 1.5 GB）两个包都装过，用内置样图，没有闪退：

| 包 | 面板上的初始内存 | `pump-room.dxf` | `tarch-note.dwg` |
| --- | --- | --- | --- |
| 调小内存 | 1024 页（64 MiB） | 约 0.04 秒，泵房和中文正常 | 约 2.08 秒，天正字「防」能看见 |
| 原始 wasm | 16384 页（1024 MiB） | 约 0.41 秒 | 约 1.61 秒 |

这台模拟器内存够，原始包也能开这张很小的天正样图。大图会不会把原始包撑死，还是要真机。

`npm test` 现在是 77 项（含 main 上的文字修复）。45000 条直线的堆增长检查改到 `npm run test:wasm-grow`，不放进每次 `npm test`，那一项大约十几秒。

「用其他应用打开」：三个 intent-filter 只按 MIME，不写路径。文件进 `incoming/<时间戳>/<原名>`，同名也不会打开旧图。`convertFileSrc` 前会对路径每一段做编码。模拟器里用 adb 发了 `content://media/external/file/1000000020`（MediaStore 里的 `pump-room-rev-b.dxf`）和外部存储的 document URI。插件都收到了，面板打出「外部打开失败」，Logcat 里有 `PeekProbe` 的警告。Android 14 不承认 adb 附带的读取授权（`has no access` / 要求 `ACTION_OPEN_DOCUMENT`），所以图没有真正打开。文件管理器选中后发出的、带授权的 `content://` 还要真机点一次。
